Settlement assurance.

Before a custodian pays a counterparty in a token on Solana, Shield decides RELEASE, REVIEW or REJECT, and on RELEASE it can pay on devnet and confirm the exact amount arrived. This answers Telegraph's Solana use case 1, institutional transaction intelligence and settlement assurance.

How to use it

Open /preflight?desk=settlement or call POST /api/preflight with mode: "settlement".

Sending. Only on RELEASE, only with execute, only on devnet, only from Shield's devnet wallet, at most 1 token. Shield waits for finalized, reads the transaction back and checks the recipient's accounts gained exactly the amount; otherwise the decision becomes REJECT.

How it is built

runSettlement in src/shield/settlement.ts: chainSettlementFindings for the reads, its own judges for each bought fact, evaluateSettlement for the decision. Solana reads, mintRestrictions, sendDevnetSettlement and verifySettlement are in src/shield/solana.ts. The devnet test tokens come from src/scripts/solana-devnet-fixtures.ts. The full write-up is telegraph/SETTLEMENT.md.
